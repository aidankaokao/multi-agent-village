# 台灣史專家：規劃與進度

> 最後更新：2026-10-17。每完成一步就更新這份文件（勾選、補上實際做法與決定）。

## 已確定的決定

1. **獨立開發、獨立部署**：放在 `extra-agents/taiwan-history/`，有自己的程式、`docker-compose.yaml`、`.env`；
   不 import 村子（`backend/`）的任何程式碼，也不和村子共用資料庫。
2. **開發完成後再接回村子**：村子用 HTTP 呼叫它（外接 agent）。村子那邊要做的是「外接村民」功能（見 T4），
   之後其他外接 agent 也走同一套。
3. **資料來源要先蒐集**：使用者手上沒有台灣史資料，由 Claude 從網路公開資料（先以中文維基百科為主）抓取、
   整理成文件，當作 RAG 的資料來源。
4. **回答的範圍、風格等之後再討論**（見「待討論」）。

```
├── docker-compose.yaml   獨立部署（之後建立）

├── app/                  服務程式（檢索、回答、A2A 介面）

```

## 階段與進度

### T0：規劃 ✅
- [x] 建立 `extra-agents/` 與本資料夾、寫下規劃

### T1：資料蒐集（Claude 負責，使用者確認清單）
- [ ] 擬定條目清單 `corpus/sources.yaml`：依時期分類（史前、大航海與荷西、明鄭、清治、日治、戰後、民主化與當代），
      每個時期的總論條目＋重要事件、人物、制度；先抓 100～200 篇，請使用者看過再擴充
- [ ] 抓取工具 `scripts/fetch_wiki.py`：用維基百科的 API 取得條目內容 → 轉成乾淨的 Markdown
      （去掉導覽框、參考文獻編號等雜訊；保留標題層級，方便之後依章節切塊）
- [ ] 每篇文件開頭記錄：標題、原始網址、版本（revision id）、抓取日期、授權
- [ ] 統一用繁體中文（中文維基的轉換：要求 zh-tw 版本）
- [ ] 資料量與品質檢查：篇數、總字數、抽查幾篇內容是否乾淨

### T2：RAG 服務本體
- [ ] 切塊：依章節（標題）切，過長再細分，每塊保留「條目 › 章節」路徑
- [ ] 向量化：embedding 模型（候選：本機 Ollama 的 bge-m3，免費、中文好；或雲端 embedding）
- [ ] 向量庫（候選：SQLite + sqlite-vec，單檔、好部署；資料變多再考慮 Postgres + pgvector）
- [ ] 檢索：向量檢索＋關鍵字（人名、年代）混合，取前幾段
- [ ] 回答：LLM 只根據檢索到的段落回答，附上引用（條目名稱＋網址）；資料裡沒有就說不知道
- [ ] 測試題：一組有標準答案的問題，量檢索與回答的正確率（之後改進 GraphRAG / agentic RAG 時當基準）

### T3：對外介面與獨立部署
- [ ] HTTP 介面：A2A 協定（`/.well-known/agent-card.json` 自我介紹 ＋ `message/send` 問答），
      另外提供簡單的 `/health` 給村子做健康檢查
- [ ] 對接用的 token（村子呼叫時帶上，避免任何人都能用它的 LLM 額度）
- [ ] `docker-compose.yaml`、`.env.example`、`./build.sh`（照村子的習慣：只 build，部署由使用者執行）
- [ ] 部署後的手動測試步驟

### T4：接回村子（改的是村子這邊）
- [ ] 村民新增「外接型」：在村民管理頁填網址（＋token），讀取 agent card 自動帶入名稱、說明、技能
- [ ] 村長可以派工給外接村民；問答時用 HTTP 呼叫，逾時與錯誤照一般村民處理
- [ ] 健康檢查：連不上時村民在村子裡顯示「外出中」，並暫時不派工
- [ ] 外接村民的動畫與角色外觀（在介面上選 sprite）

### T5：進階（之後再說）
- [ ] GraphRAG（人物、事件、地點的關係圖）或 agentic RAG（自己決定要查幾次、查什麼）
- [ ] 更多資料來源（政府開放資料、其他公開史料）

## 待討論

- **回答的範圍**：只回答資料裡有的？資料沒有時要不要用 LLM 自己的知識（並標明）？
- **回答的風格**：長度、要不要附年表、引用的呈現方式
- **它自己的 LLM 設定**：獨立 agent 用誰的 API key？（放它自己的 `.env`，還是由村子呼叫時帶過去）
  使用者是介面使用者，設定方式要再想（例如它自己也有一個簡單的設定頁）
- **embedding 模型**：本機 Ollama（免費，但容器要連主機）或雲端
- **資料清單的維護**：之後要不要能在介面上新增條目、重新抓取
- **與村子的對接細節**：A2A 協定要做到多完整（串流、任務狀態）
